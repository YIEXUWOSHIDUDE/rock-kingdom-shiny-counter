# 领域文档

本仓库采用单上下文结构。

## 开始分析前

在探索或修改代码前，应按相关性读取：

- 根目录的 `CONTEXT.md`
- `docs/adr/` 中与当前工作相关的架构决策记录

如果这些文件尚不存在，继续工作即可，不需要将缺失本身报告为问题。领域术语或架构决策得到明确确认后，再按需创建。

## 文件结构

```text
/
├── CONTEXT.md
├── docs/
│   ├── adr/
│   └── agents/
└── src/
```

## 术语规则

代码、测试、任务和设计说明应使用 `CONTEXT.md` 定义的项目术语，避免为同一概念随意创造近义词。

如果所需概念尚未定义，应判断它是错误用词还是领域模型确实存在空缺，并在后续领域梳理中处理。

## 架构决策

如果拟议修改与现有 ADR 冲突，必须明确指出冲突的 ADR 及原因，不能静默覆盖既有决策。
