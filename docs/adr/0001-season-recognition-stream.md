# ADR 0001：赛季识别方案和时序协调层

日期：2026-09-09。状态：已接受，已在 0.4.4 实现；源码交付和安装包分发状态见 `DEVELOPMENT.md`。

## 问题

关键词默认值在设置创建/加载/UI 中重复，换季时容易只改一处。原缓冲从整批取变化最大帧再清空，会丢弃两次真实提示之间的消失证据；匹配与实际加一的状态也混为一谈。

## 决定

引入不可变 `RecognitionProfile` 作为目标定义，将旧默认迁移与目标放在同一模块。现有扁平设置字段保留，用于兼容旧文件和自定义值。没有实现动态下载配置或通用插件框架。

引入 `BannerRecognitionStream`，隐藏裁剪、队列、已发出样本、文本匹配及门控的内部协作。输入完整客户端帧，输出真实裁剪样本；GPU 文本按同一样本对象返回后产生单次 `RecognitionDecision`。窗口捕获、GPU 引擎与存储仍是独立适配器，不将硬件规则混回识别配置。

队列按时间消费，只压缩相邻视觉近似片段，并按门控需要保留真实确认样本。容量为 96、排队 TTL 为 4 秒。已合法发出的 OCR 不在完成时再次按截图年龄淘汰，否则持续生产快于消费时会导致全部结果过期；它另有发出后 4 秒完成上限。暂停/捕获失败/关闭按代次使所有旧结果失效。

## 代价与验证

FIFO 在动态背景下可能接近 4 秒排队延迟，而不是即时加一。丢失空白证据、超出容量或推理时限时可能保守漏计；不能保证任意时序零漏计。保留门控已计数状态避免恢复时重复加一，但暂停期间若换成下一段提示，也可能漏计该段。

以两段提示带真实空白、持续提示、暂停在途、重复结果、自定义确认长度、持续动态积压和旧数据迁移作回归；另外使用真实 CUDA OCR 回放用户视频，分开报告模拟 Win32 与实际窗口/安装包验证。

## 2026-09-17 补充：区域入口（性能候选分支）

连续识别改用同一 MSS 后端直接抓共享 ROI，避免整窗 BGRA→BGR 转换复制。协调层增加 `offer_banner`，它接受已裁剪区域并保留独立缓冲快照；原 `offer` 完整帧入口仍裁剪一次。完整截图预览不变。这个改动不改变上述状态机、队列或失效协议。

替代方案是继续整窗后裁剪，或更换截图后端；前者作为测量基线，后者超出第一轮范围。模拟后端证实区域像素一致及转换成本降低，但真实游戏截图/DPI/流畅度仍待验证；测量证据和部署状态以 DEVELOPMENT.md 为准。

## 2026-09-17 后续授权：低置信度不作为消失证据

用户同意在性能实验之后单独修复多计。固定真实 GPU OCR 帧确认：强命中 → 连续两帧能读到目标但低于 0.55 → 强命中，会把仍在的横幅计两次。完整输入和区域输入都能触发，不能只归咎于新截图区域。

计数证据改为三态：满足原阈值的目标命中、没有目标关键词的未命中、存在低置信度目标的不确定。不确定状态打断进入/退出连续证据，保留已计数/已放行状态，既不触发计数也不完成消失确认。弱匹配使用同一关键词/规范化/分框拼接逻辑，仅用于判定不确定，不修改入场阈值或用户设置。

未选择全局降低置信度（可能增加误计），也未加固定冷却或延长消失时间（可能挡住相邻短事件）。未改变队列、推理时限、代次或线程配置。

边界：若目标被完全漏读或错字成非目标，仍按原未命中处理；本修复不解决所有 OCR 波动。若不存在目标却误读出低置信度关键词，可能保守延后重新放行，须等待后续真实未命中确认。固定真实帧回放证明此机制已修正，但不是原偶发失败的逐帧重建，且不替代游戏实机验收。
