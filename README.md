# 洛克王国异色保底计数悬浮工具

这是一个 Windows 计数器。它截取游戏客户端窗口，使用中文 OCR 寻找你设置的结算关键词，并在悬浮窗中累计保底次数。默认保底为 80 次。

程序不会访问游戏数据库，不读取游戏进程内存，不注入游戏，不模拟按键，也不执行自动战斗。正式安装包已经内置 PyTorch CUDA 运行库和 EasyOCR 中文模型，安装、启动和识别都不需要联网下载模型。源代码运行时若模型缺失，会优先尝试带 SHA-256 校验的国内来源。计数、设置、OCR 模型、历史记录和诊断日志保存在 `%APPDATA%\RockKingdomShinyCounter\`。

开发决策、历次更新、已知问题、诊断失误和发布检查清单统一记录在 [DEVELOPMENT.md](DEVELOPMENT.md)。

> 风险提示：官方公开口径禁止第三方辅助工具。即使本程序只读取屏幕，也不能保证账号不会受到处罚。请先向腾讯客服确认，主账号谨慎使用。

## 最低运行要求

- Windows 10 22H2 或 Windows 11（64 位）
- NVIDIA GeForce RTX 20/30/40/50 系显卡，CUDA 计算能力不低于 7.5
- NVIDIA Windows 驱动 570.65 或更高版本
- 至少 4 GB 显存、8 GB 内存，建议 16 GB 内存
- 安装或覆盖更新时至少预留 5 GB 可用磁盘空间；安装器直接从内嵌载荷解压，不再额外复制约 2 GB 临时压缩包

程序只支持 NVIDIA GPU OCR，不提供 CPU 降级模式。显卡、驱动或安装包 CUDA 架构不满足要求时，会直接显示具体原因。

安装器会在解压前自动检测 Windows 版本、系统位数、安装盘空间、NVIDIA 显卡、显存、驱动版本和 CUDA 计算能力。所有项目都必须明确通过；无法可靠读取 GPU、驱动或计算能力时也会停止安装，不会用“未知”绕过 GPU-only 要求。解压后，安装器还会在暂存目录运行新版本自己的 CUDA 张量、EasyOCR 模型加载和固定图片推理。只有真实 GPU 推理通过才替换旧版本；失败时旧版本保持不变。

## 源代码环境与安装

- 64 位 Python 3.13
- 洛克王国使用窗口化或无边框窗口模式

如果你安装过旧的模板识别版，建议先删除旧 `.venv`，再按下列步骤重建环境，避免 `opencv-python` 与 `opencv-python-headless` 同时存在。原有 `%APPDATA%\RockKingdomShinyCounter\data.json` 可以继续使用。

在 PowerShell 中执行：

```powershell
cd rock-kingdom-shiny-counter
py -3.13 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

从 PyTorch 官方 CUDA 12.8 索引安装固定版本，然后继续安装其余依赖：

```powershell
python -m pip install -r requirements-cuda.txt
python -m pip install -r requirements.txt
python -c "import torch; print('CUDA available:', torch.cuda.is_available(), 'CUDA:', torch.version.cuda, 'architectures:', torch.cuda.get_arch_list())"
python -m shiny_counter
```

必须输出 `CUDA available: True`。RTX 50 系还必须在架构列表中看到 `sm_120`；如果缺失，请确认安装的是 CUDA 12.8 构建。

完成上述安装后，可以直接双击 `run.bat`。脚本会优先使用项目内的 `.venv`。

## 首次使用 OCR

1. 启动洛克王国客户端，使用窗口化或无边框窗口模式。
2. 启动计数器，点击“选窗口”，选择游戏客户端。无需框选截图区域。
3. 点击“测试截图”。预览中的红框必须覆盖游戏顶部中央通知横幅；否则先解决窗口捕获问题。
4. 安装版会从安装包加载 EasyOCR 中文模型，请等待识别就绪。
5. 当前源码默认采用“S4 星星横幅”，关键词是“划破天幕坠落”，对应“精灵藏进星星，划破天幕坠落！”提示。
6. 进入一次有效结算画面，核对计数；需要排查时点击“查看文字”。只有计数真正触发时状态栏才显示“计数 +1”，持续命中显示“等待本次提示结束”。
7. 如需自定义，打开“设置”修改“OCR 关键词”。多个关键词用逗号分隔；应选择只在有效结算画面出现的短语。

旧数据没有识别方案标识且关键词恰好为旧默认“写进了童话里”时，会迁移到 S4 默认词；其他自定义关键词、置信度、扫描间隔、计数和历史保留。旧格式无法区分“接受旧默认”与“手工填写完全相同的旧词”。已有方案标识的配置不会反复迁移；不认识的方案标识会报错，不静默覆盖。

默认在顶部中央横幅区域扫描。截图线程每 50 ms 捕获一次；GPU OCR 忙碌时截图不会停止。缓冲区最多 96 张真实样本，排队保留最长 4 秒，按捕获时间先后消费，不再取全局变化最大帧后清空整批。只压缩相邻且视觉近似的片段，保留足够的真实确认帧；像素变化本身不代表横幅命中或消失。

一次 OCR 命中后计数一次，关键词持续显示时不重复计数；默认连续两次 OCR 未命中后才允许下一次计数。GPU OCR 默认最小调度间隔 200 ms、最低置信度 0.55，推理绝不回退到 CPU。排队时已过期的帧不再启动识别；合法取出的帧允许在最多 4 秒的单次推理窗口内完成。暂停、捕获中断或关闭立即使之前在途结果失效，恢复时不凭空假定横幅已经消失。

这些是有界缓冲策略，不是零漏计或低延迟保证。持续动态背景下可能出现接近 4 秒的排队延迟，再加本次推理耗时；缓冲溢出、长时间暂停、确认帧不足或单次推理超过 4 秒仍可能漏计，应使用“补一”修正。S4 请使用 0.4.4 或相应后续版本；旧安装包不会因源码更新自动获得新逻辑。

0.4.5 修复关闭窗口后后台进程残留：“×”和托盘“退出”都会在保存数据、停止后台任务后退出程序。若 GPU OCR 尚未结束，程序会提示稍后重试，不会强杀识别线程。

从旧版升级前请先退出旧计数器。如果旧版窗口已消失但安装仍提示文件被占用，在任务管理器中结束 `RockKingdomShinyCounter.exe` 后再安装；无需结束游戏或删除计数数据。

游戏窗口可以移动。窗口尺寸、系统缩放或游戏界面发生变化时，工具会暂停并要求重新选择窗口。

## 使用说明

- “补一”：修正漏识别。
- “撤销”：将当前计数减一并写入历史。
- “暂停”：停止截图识别，手动操作仍可用。
- “解锁位置/锁定位置”：默认锁定悬浮窗，解锁后才允许鼠标拖动。
- “重置”：确认后结束当前轮次并开始新一轮，自动记录本轮次数、保底上限和是否达到保底。
- “查看文字”：查看最近一次顶部横幅 OCR 识别到的文字，用于选择关键词。
- “测试截图”：立即捕获已选游戏窗口，并用红框显示实际 GPU OCR 区域。
- “历史”：先直观查看“第几轮、多少次出、是否提前或超过保底”，再查看自动计数、手动计数、撤销、重置和到达保底事件。
- 旧版数据中的重置事件会自动回填为“多少次出（旧记录）”；由于旧数据没有保存当时的保底上限，不会推测提前或超过保底的次数。
- “导出”：生成包含 `data.json` 的 ZIP；OCR 模型不会打包。
- “导入”：验证 ZIP 后替换当前数据，并在数据目录中生成导入前备份。

默认不注册任何全局快捷键，启动时不会因为键位占用而弹窗。“补一”“撤销”“暂停”只通过悬浮窗按钮操作。

需要点击穿透时，在“设置 → 高级设置”中主动开启。开启后可以通过系统托盘菜单“关闭点击穿透”恢复操作；如果系统托盘不可用，则必须同时启用并设置一个“关闭穿透”全局快捷键。单个快捷键注册失败时只会在悬浮窗状态栏提示，不会弹窗打断启动。

## 识别边界

OCR 可能漏字或识别错字。低置信度文字按设计不计数，因此建议先用“查看文字”确定稳定关键词，并偶尔核对当前次数。若关键词在非结算画面也出现，会造成误计；应换成更独特的短语。遮挡、独占全屏、过小字体和游戏更新都可能影响识别。工具不会自动重置已达到保底的计数。

发生问题时先点“测试截图”，再查看状态栏中的错误代码。详细异常写在 `%APPDATA%\RockKingdomShinyCounter\logs\diagnostics.jsonl`；反馈时请同时提供安装包 SHA-256、错误代码和对应日志。
